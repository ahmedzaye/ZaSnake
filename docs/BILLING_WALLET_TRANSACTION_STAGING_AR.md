# Za Snake — مسودة Firestore Paid Wallet v1

## الوضع الحالي المؤكد
- نشر Cloud Run Billing الخاص نجح.
- نشر Mobile Gateway نجح، مع `GATEWAY_ENABLED=false` و`--no-allow-unauthenticated`.
- اختبارات الشبكة: `403` بدون IAM، `200` عند قراءة Health بهوية مصرح لها، `503` لجلسة شراء عندما تكون البوابة معطلة.
- تطبيق Firebase App Check مسجّل مع Play Integrity في مشروع `zasnake`، وحفظ رمز Debug في Console.

## التغيير الجديد
- `backend/wallet_repository.py` هو نموذج منفصل لمستند `paid_wallets_v1/{sha256(playerId)}`.
- يتضمن معاملة Firestore للعمليات الانتقالية، ويفرض معرف عملية ثابتًا ومبالغ 1000/2000/4000 بعد تحقق Google Play، ومفاتيح صرف وثابتة وتراجع استرداد monotonic.
- يرفض خرائط العملات غير الصحيحة أو تضخم حجم المستندات.
- `backend/tests/test_wallet_repository.py` يقدم اختبارات حراسة وسلامة البيانات — لا يغطي المحاكاة الكاملة لـFirestore ولا طلبات Google Play.

## تنبيهات حرجة
1. الكود الجديد **غير مستخدم** في `backend/main.py`، ولم يُنشر في Cloud Run. لا يغير أرصدة المستخدمين أو عمليات الشراء.
2. ليس مقبولًا ربط `credit_verified_purchase` بنقطة `/claim` مباشرة حتى تُنفَّذ **معاملة موحّدة** تُنهي حالة الشراء وتضيف العملات مرة واحدة في نفس Firestore transaction، مع معالجة إعادة المحاولة عندما ينجح consume وتفشل الكتابة.
3. يجب تحديد سياسة انتقال تحافظ على العملات المجانية والأشكال المشتراة بالفعل في ملفات الحفظ، وتمنع اختراع أرصدة مدفوعة من بيانات محلية قابلة للتلاعب.
4. `spend_verified_item` لا يجوز توفيره كواجهة عامة قبل مراجعة ملكية العناصر والأرصدة الحرة والعمليات المتزامنة. قائمة الأسعار هي مسودة للمراجعة.
5. لا توجد معالجة RTDN وVoided Purchases API، ولا إعادة تسوية دورية أو تحكم في إساءة الاستخدام. لا تُفعّل `GATEWAY_ENABLED` أو `billingIntegrationEnabled`.
6. المعاملات الحقيقية/تحت الاختبار لا تبدأ قبل نجاح سيناريوهات الاسترداد والقطع والتكرار وتغيير الأجهزة.
7. حد `MAX_EVENTS_PER_WALLET` مؤقت. يلزم تصميم شارد/سجل دائم لتراكم عمليات الشراء غير المحدود قبل الإنتاج.

## اختبار أولي على Cloud Shell أو جهازك
داخل جذر المشروع، مع تثبيت `backend/requirements.txt`:
```bash
cd backend
python3 -m unittest discover -s tests -v
```
لا تختبر برموز شراء حقيقية في أوامر أو سجلات مكشوفة.

## ما بعد هذه المسودة
بناء معاملات شراء/رصيد كاملة وتسجيل أحداث رد الأموال الموثقة، ثم اختبارات Firebase emulator / Firestore transactions، وبعدها نشر staging خاص واختبار App Check/Game Server OAuth على جهاز حقيقي.
