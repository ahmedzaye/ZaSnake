# Za Snake — صرف العملات المدفوعة وعناصر المتجر (مرحلة تجريبية فقط)

## الوضع الحالي
- أثناء انتظار حل Google Play API `HTTP 401 permissionDenied`، أضفنا وحدة مستقلة `backend/paid_item_entitlements.py`.
- **لم ننشر أي خدمة جديدة، ولم نفعّل أي Endpoint أو شراء أو صرف عملات.**
- حساب مراجعة الاستردادات `zasnake-voided-review` لا يحتاج صلاحيات كتابة ولا يجب تشغيل هذه الوحدة به.
- اللعبة حاليًا تسمح بشراء الأشكال والثيمات بالعملات المجانية/المحلية. النظام الجديد **ليس بديلًا لها بعد**، ولا يغيّر البيانات الموجودة.

## التصميم
1. كل أسعار العناصر تأتي من `PREMIUM_ITEM_PRICES` المخزن على الخادم، وليس من طلبات Android.
2. العملات المدفوعة تدخل `paid_wallets_v1/{SHA256(playerId)}` فقط بعد تحقق Play من ملكية وتأكيد عملية شراء موثقة (تحت حماية مسار الشراء الذي لم يُفعّل بعد).
3. شراء عنصر باستخدام *العملات المدفوعة حصريًا* يكتب `item:<itemId>` في `spends` داخل نفس معاملة Firestore التي تخصم الرصيد.
4. تكرار الطلب من جهاز آخر لن يخصم العملات ثانية لأن مفتاح العنصر ثابت، وتتحقق معاملة Firestore من الحالة الحالية.
5. إذا حدث استرداد بعد الشراء، يحتفظ السجل بمصروف العنصر والدين؛ لا تُمنح عملات مجددًا ولا يُحذف العنصر تلقائيًا حتى يُحدد قرار المنتج.
6. `read_paid_item_ids_staging` يقرأ ملكية العناصر التي اشتُريت *بالعملات المدفوعة* من الخادم، لا من ملف الحفظ المحلي.
7. لا يوجد Endpoint عام، ولا طلب سعر أو playerId من هاتف، ولا اعتماد على OAuth غير مكتمل.

## عوائق قبل الربط
- سياسة واضحة وموحدة للأرصدة المجانية والمحلية والمدفوعة حتى لا يضيع رصيد قديم أو يتم الخصم مرتين.
- حل مسألة ملكية العناصر التاريخية وعمليات الشراء السابقة في Play Games/cloud saves.
- مصادقة Play Games من Gateway مع App Check، واستخدام هوية اللاعب من جلسة خادم فعلية.
- تطبيق قيود المعدل ومكافحة إساءة الاستخدام على الطلبات الفعلية.
- تسوية الاستردادات وRTDN وتحقق المنتج من Google Play، ثم اختبار License Tester حقيقي.
- قرار واضح بشأن الاحتفاظ بالعناصر التي سبق صرف عملات مدفوعة عليها ثم استُرد ثمن مصدرها.
- التحويل إلى سجل أحداث قابل للتوسع قبل الوصول إلى حد `MAX_EVENTS_PER_WALLET` (150).
- مراجعة تزامن تحديث الأسعار مع بيانات Android.

## اختبارات Cloud Shell (دون Firestore حقيقي)
```bash
cd ~/zasnake-gateway-source
git fetch origin feature/paid-item-entitlement-staging
git switch --detach origin/feature/paid-item-entitlement-staging
cd backend
source .venv/bin/activate
unset FIRESTORE_EMULATOR_HOST
python3 -m unittest discover -s tests -v
```
المتوقع: **89 اختبارًا، 80 ناجحًا و9 متخطاة** (6 للمحفظة السابقة و3 جديدة لمحاكي Firestore) بعد إضافة 8 اختبارات قواعد و3 للمحاكي.

## اختبار Firestore Emulator
فعّل المحاكي المحلي فقط إذا كان جاهزًا ثم استخدم `FIRESTORE_EMULATOR_HOST=127.0.0.1:8085`. تأكد أن الطرف الذي يعمل عليه المحاكي موجود وألا تستخدم عنوان قاعدة Firestore الحقيقية.
